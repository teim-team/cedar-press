# Cedar Press datasets: the old-to-new field map

Generated from `data/cedar/field_map.json` by `scripts/field-map-markdown.mjs`; edit the JSON, not this file. Written 2026-09-05.

## What this is

The first step `docs/PUBLIC_DATASET_SPEC_2026-09-05.md` §17 asks for: an inventory of every column each flagship table carries today, with one decision per column, and the approved public header each dataset ships with. The customer-file writer (`code/1137_customer_dataset_combine.py` through `cedar_publication.apply_field_map`) generates the export from this list: it renames, drops what is internal or documented, fills the opening block from the register, orders the header as `order` says, and refuses to build a dataset whose flagship carries a column with no decision here, so a new upstream field needs a publication decision before it can reach a customer.

Written against the ten-row samples in `public/data/cedar/samples/`. A decision is validated by the terminal against the full table before it is applied: a blank in ten rows proves nothing, and a `combine` is owed until its sources have been tested for agreement.

**Decisions:**

- `keep`: Ships under its current name.
- `rename`: Ships under the name in `to`.
- `combine`: Folds into the target field named in `to` once the terminal has tested that the sources agree; until then it stays in the workspace and the target is owed.
- `derive`: Its content reaches the customer file as a derived field named in `to`; the column itself stays in the workspace.
- `document`: Leaves the file; what it says is stated once in the researcher guide.
- `internal`: Stays in the workspace for reproducibility and review; never ships.
- `withhold`: Ships as a column; cells are masked where the publication policy applies, never the column.

**The opening block, in every dataset:**

- `cedar_uid`: The permanent identifier of the Native entity the row is attributed to; a pipe-separated list where a row names several. Never the record's own id.
- `cedar_entity_name`: That entity's name as the register spells it (data/spine/cedar_entity_names.csv, by uid), written at build time; withheld where the publication rule says so.
- `cedar_entity_type`: That entity's class as the register holds it (one of eighteen), written at build time from the uid; never a scope, a source's own type or the record subject's kind.
- `cedar_entity_role`: Why the entity is on the row: recipient, owner of the awardee, client, participant, culturally affiliated, certifying authority. Constant per table or read from a role column, as each table declares.
